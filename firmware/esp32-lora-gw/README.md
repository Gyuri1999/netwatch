# NetWatch LoRa Gateway (ESP32 + SX1276)

Η **πύλη** για τους κόμβους [`../esp32-lora-node`](../esp32-lora-node/README.md). Ακούει συνεχώς
στο LoRa, ελέγχει κάθε πακέτο (HMAC-SHA256 + μετρητή κατά του replay), κρατά πίνακα κόμβων και
τον στέλνει στο NetWatch μέσω Wi-Fi (τύπος **`lora`**).

| Τι | Πώς | Στο NetWatch |
|---|---|---|
| Πίνακας κόμβων | ένα `items` ανά κόμβο που ακούστηκε | `node`, `rssi`, `snr`, `batt`, `temp`, `hum`, `door`, `age`, `seq` |
| Άνοιγμα πόρτας | από τις σημαίες του πακέτου | γεγονός `door_open` |
| Ζέστη | `LORA_TEMP_HIGH_C` με υστέρηση | γεγονός `temp_high` |
| Μπαταρία | `LORA_BATT_LOW_V` ή σημαία του κόμβου | γεγονός `batt_low` |
| Κόμβος που σώπασε | κανένα πακέτο για **3 ×** την περίοδό του | γεγονός `lora_node_lost` (`data.node`) |

Είναι LoRa **σημείο-προς-σημείο**, **όχι LoRaWAN**. Η πύλη **δεν εκπέμπει ποτέ** στο LoRa.

> **Δοκιμασμένο μόνο σε compile· δεν έχει τρέξει σε πραγματικό υλικό.** Δες την ενότητα 8.

## 1. Υλικό και τιμές (ενδεικτικά)

| Εξάρτημα | Τιμή |
|---|---|
| TTGO LoRa32 (V1 / T3 V1.6.1) ή Heltec WiFi LoRa 32 **V2**, **SX1276, 868 MHz** | ~20 € |
| Κεραία 868 MHz, όσο πιο ψηλά και ελεύθερα γίνεται | στη συσκευασία |
| Τροφοδοτικό USB | – |

Πλακέτες με **SX1262** (Heltec V3) δεν υποστηρίζονται. Καμία εξωτερική βιβλιοθήκη.

## 3. Συνδεσμολογία

Όλα είναι πάνω στην πλακέτα. Προεπιλογές (αλλάζουν στο `secrets.h`):

| Σήμα | TTGO LoRa32 V1 / Heltec V2 | TTGO T3 V1.6.1 |
|---|---|---|
| SCK / MISO / MOSI | 5 / 19 / 27 | 5 / 19 / 27 |
| NSS (CS) | 18 | 18 |
| RESET | 14 | **23** (`PIN_LORA_RST 23`) |
| DIO0 | 26 (δεν χρησιμοποιείται: γίνεται polling) | 26 |
| Κουμπί PRG/BOOT | 0 | 0 |

Βάλε την πύλη εκεί που **έχει Wi-Fi** και όσο πιο κοντά/ψηλά γίνεται προς τους κόμβους.

## 4. Ρύθμιση και σύζευξη

```bash
cd ~/netwatch/firmware/esp32-lora-gw
cp secrets.example.h secrets.h
```

1. Στο NetWatch: **🧩 Οι συσκευές μου → κάρτα «LoRa» → Δημιουργία κωδικού → Αντιγραφή**.
2. Στο `secrets.h`: `WIFI_SSID`, `WIFI_PASS`, ο κωδικός στο `NW_PAIR_CODE`.
3. `LORA_KEY_HEX`: το **ίδιο** κλειδί με τους κόμβους (`openssl rand -hex 32`). Με την τιμή του
   προτύπου η πύλη δεν δέχεται **κανένα** πακέτο.
4. `LORA_FREQ_HZ`, `LORA_SF`, `LORA_BW_HZ`, `LORA_CR`: **ίδια** με των κόμβων.
5. Όρια: `LORA_TEMP_HIGH_C`, `LORA_TEMP_HYST_C`, `LORA_BATT_LOW_V`.

Οι κόμβοι **δεν δηλώνονται** πουθενά: όποιος στείλει πακέτο με σωστό HMAC μπαίνει στον πίνακα
(έως 24). Ο κωδικός σύζευξης περιέχει το token **και** το αποτύπωμα SHA-256 του πιστοποιητικού
του NetWatch· αν δεν ταιριάζει, το firmware **δεν στέλνει τίποτα**.

## 5. Flash

### arduino-cli

```bash
cd ~/netwatch/firmware/esp32-lora-gw
arduino-cli compile --fqbn esp32:esp32:esp32 --library ../common .
arduino-cli upload  --fqbn esp32:esp32:esp32 -p /dev/cu.usbserial-0001 .
arduino-cli monitor -p /dev/cu.usbserial-0001 -c baudrate=115200
```

### Arduino IDE

1. Boards Manager: **esp32 by Espressif** (3.x).
2. Μία φορά: `ln -s "$(cd ../common && pwd)" ~/Documents/Arduino/libraries/NetWatchSignedOta`.
3. Board **ESP32 Dev Module** (ή η πλακέτα σου), **Upload**, Serial Monitor στα **115200**.

## 6. Τι θα δεις

Στο Serial:

```text
[lora] SX1276 ok: 868.100 MHz SF9 BW125000 CR4/5, packet air time 206 ms
[nw] paired as p-1a2b3c4d (kind=lora)
[lora] n7 seq=1234 rssi=-97 snr=7.5 batt=3.91 temp=23.4 hum=56 door=1 flags=0x07
[nw] report ok: 1 nodes (next in 60 s)
```

Στο NetWatch:

```json
{"status":{"fw":"1.0.0","hw":"ESP32 LoRa gateway (SX1276)","ip":"192.168.1.63","mac":"a4:cf:12:aa:bb:cc","uptime":3600,"heap":210000,
  "rssi":-52,"interval":60,"metrics":{"nodes":1,"rx_ok":17,"rx_bad":0,"replay":0,"radio":true}},
 "events":[{"type":"door_open","detail":"Άνοιξε η πόρτα στον κόμβο LoRa n7","data":{"node":"n7","door":true}}],
 "items":[{"node":"n7","rssi":-97,"snr":7.5,"batt":3.91,"temp":23.4,"hum":55.5,"door":true,"age":12,"seq":1234}]}
```

- `age` = δευτερόλεπτα από το τελευταίο πακέτο του κόμβου. `temp`/`hum`/`door`/`batt` λείπουν
  αν ο κόμβος δεν έχει τον αντίστοιχο αισθητήρα.
- `metrics.rx_bad` = πακέτα που απορρίφθηκαν (ξένο LoRa, άλλο κλειδί ή **πλαστό**)·
  `metrics.replay` = πακέτα με παλιό μετρητή. Αν ανεβαίνουν χωρίς λόγο, κάποιος παίζει στη συχνότητά σου.
- Κάθε φρέσκο πακέτο προκαλεί αναφορά μέσα σε ~2 s· αλλιώς κάθε `REPORT_INTERVAL_S`.

## 7. Αντιμετώπιση προβλημάτων

| Σύμπτωμα | Τι να κοιτάξεις |
|---|---|
| `SX1276 NOT FOUND` | λάθος pins (RESET 14 ή 23;) ή πλακέτα με SX1262· ξαναδοκιμάζει κάθε 30 s |
| `rejected … (not ours / bad HMAC)` | άλλο κλειδί στον κόμβο, ή ξένη κίνηση LoRa (φυσιολογικό σε πόλη) |
| `REPLAY/old counter` | ο κόμβος έχασε τον μετρητή του (Erase All Flash): κράτα το **PRG 3 s στην εκκίνηση** της πύλης για να σβήσεις τους αποθηκευμένους μετρητές. Αν δεν άλλαξες τίποτα, κάποιος ξαναπαίζει παλιά πακέτα |
| δεν ακούγεται τίποτα | διαφορετικά SF/BW/συχνότητα, κεραία, απόσταση· δοκίμασε πρώτα με τον κόμβο στο ίδιο δωμάτιο |
| `lora_node_lost` ενώ ο κόμβος δουλεύει | οριακό σήμα (δες `rssi`/`snr`): ανέβασε το `LORA_SF` **και στα δύο**, ή πλησίασε την πύλη |
| `CERT MISMATCH … token NOT sent` | νέο πιστοποιητικό στο NetWatch ή παρεμβολή: νέα σύζευξη / έρευνα |

## 8. Όρια και ασφάλεια

- **EU868:** η πύλη μόνο ακούει, άρα δεν έχει θέμα duty cycle ή ισχύος. Οι κανόνες (1 %,
  14 dBm ERP) επιβάλλονται στον κόμβο· δες την ενότητα 8 του README του.
- **Replay:** πακέτο με `seq` ≤ του τελευταίου αποδεκτού από τον ίδιο κόμβο αγνοείται. Ο
  τελευταίος μετρητής κάθε κόμβου γράφεται στο NVS σε **κάθε** αποδεκτό πακέτο (με περίοδο 15
  λεπτών είναι ~100 εγγραφές τη μέρα ανά κόμβο· το NVS κάνει wear levelling), ώστε μια
  επανεκκίνηση της πύλης να μην ξανανοίγει την πόρτα σε παλιά πακέτα.
- **Πρώτη επαφή:** από κόμβο που η πύλη δεν έχει ξαναδεί γίνεται δεκτός οποιοσδήποτε μετρητής.
- **Πιστοποίηση, όχι κρυπτογράφηση:** τα δεδομένα των κόμβων ταξιδεύουν σε καθαρή μορφή.
- **Μία συχνότητα, ένα SF:** η πύλη ακούει μόνο τη ρύθμισή της. Δύο κόμβοι που εκπέμψουν την
  ίδια στιγμή συγκρούονται και χάνονται και οι δύο (δεν υπάρχει ACK/επανάληψη).
- Όσο γίνεται η αναφορά HTTPS (~1–3 s) το ραδιόφωνο συνεχίζει να ακούει, αλλά κρατά μόνο το
  **τελευταίο** πακέτο· ένα δεύτερο μέσα στο ίδιο διάστημα χάνεται.
- Μετά από επανεκκίνηση της πύλης ο πίνακας είναι άδειος μέχρι να ξανακουστεί κάθε κόμβος, και
  κόμβος που δεν ξανακουστεί ποτέ **δεν** θα βγάλει `lora_node_lost` (η πύλη δεν θυμάται ότι υπήρχε).
- Το κλειδί LoRa, ο κωδικός Wi-Fi και το token είναι στη flash: όποιος πάρει την πλακέτα τα διαβάζει.

**Πιθανότερα σημεία προσαρμογής σε πραγματικό υλικό:** pin RESET ανά αναθεώρηση πλακέτας, η
σταθερά RSSI (−157 για τη θύρα HF του SX1276), και το polling του καταχωρητή IRQ κάθε 5 ms
(αν χάνονται πακέτα σε πυκνή κίνηση, θέλει interrupt στο DIO0).
