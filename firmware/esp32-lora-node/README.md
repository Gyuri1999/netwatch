# NetWatch LoRa Node (ESP32 + SX1276)

Αισθητήρας **μπαταρίας** για μέρη **χωρίς Wi-Fi** (αποθήκη, υπόγειο, αντλιοστάσιο, πυλωρείο).
Κοιμάται σε deep sleep, ξυπνά όταν αλλάξει η πόρτα ή κάθε `LORA_INTERVAL_S`, στέλνει **ένα**
πακέτο LoRa 24 bytes και ξανακοιμάται. Το ακούει η πύλη [`../esp32-lora-gw`](../esp32-lora-gw/README.md),
που το προωθεί στο NetWatch.

| Τι στέλνει | Πώς |
|---|---|
| Πόρτα (ανοιχτή/κλειστή, «άλλαξε») | μαγνητική επαφή, ξύπνημα ext0 |
| Θερμοκρασία, υγρασία | SHT31 σε I2C (προαιρετικός, ανιχνεύεται μόνος του, έλεγχος CRC) |
| Τάση μπαταρίας | ADC με διαιρέτη |
| Μετρητής `seq`, περίοδος, σημαίες | για προστασία από replay και για το «χάθηκε ο κόμβος» |

Είναι LoRa **σημείο-προς-σημείο**, **όχι LoRaWAN**: κανένα join, κανένας network server, καμία
απάντηση (ACK). Ο κόμβος δεν ακούει ποτέ και δεν έχει Wi-Fi/Bluetooth.

> **Δοκιμασμένο μόνο σε compile· δεν έχει τρέξει σε πραγματικό υλικό.** Δες την ενότητα 9.

## 1. Υλικό και τιμές (ενδεικτικά)

| Εξάρτημα | Τιμή |
|---|---|
| TTGO LoRa32 (V1 / T3 V1.6.1) ή Heltec WiFi LoRa 32 **V2**, **SX1276, 868 MHz** | ~20 € |
| Κεραία 868 MHz (**ποτέ εκπομπή χωρίς κεραία**) | στη συσκευασία |
| Μπαταρία LiPo 3,7 V ή 18650 | ~5 € |
| SHT31 breakout, μαγνητική επαφή | ~3 € + ~1 € |
| Αντίσταση 1 MΩ (pull-up πόρτας, συνιστάται) | – |

Οι πλακέτες **V3** της Heltec και οι T-Beam Supreme έχουν **SX1262**: δεν υποστηρίζονται.
Καμία εξωτερική βιβλιοθήκη: SX1276 με ωμό SPI (`../common/nw_lora.h`), HMAC από το mbedtls του πυρήνα.

## 3. Συνδεσμολογία

Το LoRa είναι πάνω στην πλακέτα. Προεπιλογές (όλα αλλάζουν στο `secrets.h`):

| Σήμα | TTGO LoRa32 V1 / Heltec V2 | TTGO T3 V1.6.1 |
|---|---|---|
| SCK / MISO / MOSI | 5 / 19 / 27 | 5 / 19 / 27 |
| NSS (CS) | 18 | 18 |
| RESET | 14 | **23** (`PIN_LORA_RST 23`) |
| DIO0 | 26 (δεν χρησιμοποιείται: γίνεται polling) | 26 |
| Μπαταρία (ADC) | Heltec V2: GPIO37, διαιρέτης 3.2, `PIN_BATT_CTRL 21` | GPIO35, διαιρέτης 2 |

| Αισθητήρας | Ακροδέκτης | ESP32 | Σημείωση |
|---|---|---|---|
| Reed πόρτας | δύο καλώδια | `PIN_DOOR` (GPIO13) και GND | **μόνο RTC GPIO** (0, 2, 4, 12–15, 25–27, 32–39) |
| Pull-up πόρτας | 1 MΩ | `PIN_DOOR` → 3V3 | και `DOOR_INTERNAL_PULLUP 0` (βλ. κατανάλωση) |
| SHT31 | VIN / GND / SDA / SCL | 3V3 / GND / GPIO21 / GPIO22 | Heltec V2: το 21 είναι το Vext → διάλεξε άλλα pins |

Η TTGO LoRa32 V1 **δεν** έχει διαιρέτη μπαταρίας πάνω στην πλακέτα: βάλε δικό σου
(π.χ. 2 × 100 kΩ προς ένα pin του ADC1) ή `USE_BATT 0`.

**Κατανάλωση πόρτας:** το εσωτερικό pull-up (~45 kΩ) με κλειστή επαφή τραβά ~70 µA συνεχώς,
δηλαδή όσο όλος ο υπόλοιπος ύπνος. Με εξωτερικό 1 MΩ πέφτει στα ~3 µA.

## 4. Ρύθμιση

```bash
cd ~/netwatch/firmware/esp32-lora-node
cp secrets.example.h secrets.h
openssl rand -hex 32          # το κοινό κλειδί: ΙΔΙΟ στην πύλη και σε όλους τους κόμβους
```

Στο `secrets.h`:

1. `LORA_NODE_ID`: μοναδικός αριθμός ανά κόμβο (στο NetWatch φαίνεται ως `n<αριθμός>`).
2. `LORA_KEY_HEX`: τα 64 δεκαεξαδικά ψηφία. Με την τιμή του προτύπου ο κόμβος **αρνείται να εκπέμψει**.
3. `LORA_FREQ_HZ`, `LORA_SF`, `LORA_BW_HZ`, `LORA_CR`: **ίδια** με της πύλης.
4. `LORA_INTERVAL_S` (προεπιλογή 900 s) και τα pins της πλακέτας σου.

Ο κόμβος δεν έχει κωδικό σύζευξης NetWatch: η σύζευξη γίνεται **στην πύλη**.

## 5. Flash

### arduino-cli

```bash
cd ~/netwatch/firmware/esp32-lora-node
arduino-cli compile --fqbn esp32:esp32:esp32 --library ../common .
arduino-cli upload  --fqbn esp32:esp32:esp32 -p /dev/cu.usbserial-0001 .
arduino-cli monitor -p /dev/cu.usbserial-0001 -c baudrate=115200
```

(Δουλεύουν και τα `esp32:esp32:ttgo-lora32`, `esp32:esp32:heltec_wifi_lora_32_V2`· τα pins τα
ορίζει έτσι κι αλλιώς το `secrets.h`.)

### Arduino IDE

1. Boards Manager: **esp32 by Espressif** (3.x).
2. Μία φορά: `ln -s "$(cd ../common && pwd)" ~/Documents/Arduino/libraries/NetWatchSignedOta`.
3. Board **ESP32 Dev Module** (ή η πλακέτα σου), **Upload**, Serial Monitor στα **115200**.

Όσο κοιμάται, η θύρα USB μπορεί να μην απαντά: πάτα RESET ή άνοιξε/κλείσε την επαφή για upload.

## 6. Τι θα δεις

Στο Serial, σε κάθε ξύπνημα (διαρκεί ~1 s):

```text
[node] NetWatch LoRa Node 1.0.0 id=7 wake=2
[node] sent seq=1234 batt=3912 mV temp=23.45 hum=55.5 door=1 flags=0x07 air=412 ms
[node] sleep 900 s
```

`wake=2` = πόρτα (ext0), `wake=4` = χρονόμετρο. Στο NetWatch ο κόμβος εμφανίζεται ως γραμμή στον
πίνακα της πύλης (`node`, `rssi`, `snr`, `batt`, `temp`, `hum`, `door`, `age`, `seq`).

## 7. Μορφή πακέτου και διάνυσμα ελέγχου

24 bytes, little-endian (ορισμός: `../common/nw_lora.h`):

| Θέση | Μήκος | Πεδίο |
|---|---|---|
| 0 | 1 | magic `0x4E` |
| 1 | 1 | έκδοση `0x01` |
| 2 | 2 | id κόμβου |
| 4 | 4 | `seq` (μόνο ανεβαίνει) |
| 8 | 2 | μπαταρία σε mV (0 = δεν μετριέται) |
| 10 | 2 | θερμοκρασία σε εκατοστά °C, προσημασμένη (`0x7FFF` = δεν υπάρχει) |
| 12 | 1 | υγρασία σε μισά % (`0xFF` = δεν υπάρχει) |
| 13 | 1 | σημαίες: `0x01` πόρτα ανοιχτή, `0x02` γεγονός πόρτας, `0x04` έχει επαφή, `0x08` πρώτη εκκίνηση, `0x10` χαμηλή μπαταρία |
| 14 | 2 | περίοδος σε s |
| 16 | 8 | τα πρώτα 8 bytes του HMAC-SHA256(κλειδί, bytes 0–15) |

Έλεγχος στον υπολογιστή (ίδιο αποτέλεσμα βγάζει και ο κώδικας C του `nw_lora.h`· ελέγχθηκε σε host):

```bash
python3 - <<'EOF'
import hmac, hashlib, struct
key  = bytes(range(32))                                   # 000102…1f  (ΜΟΝΟ για τον έλεγχο!)
body = struct.pack('<BBHIHhBBH', 0x4E, 1, 7, 1234, 3912, 2345, 111, 0x05, 900)
print((body + hmac.new(key, body, hashlib.sha256).digest()[:8]).hex())
EOF
# 4e010700d2040000480f29096f0584030ceead2f35909287
```

(κόμβος 7, seq 1234, 3,912 V, 23,45 °C, 55,5 %, πόρτα ανοιχτή + έχει επαφή, περίοδος 900 s)

## 8. EU868: τι επιβάλλει ο κώδικας

- **Ζώνη 868,0–868,6 MHz** (προεπιλογή 868,1 MHz): **1 % duty cycle**, έως **25 mW ERP = 14 dBm**.
- **Ισχύς:** `LORA_TX_DBM` πάνω από 14 **δεν μεταγλωττίζεται**. Τα 14 dBm είναι ισχύς στην έξοδο
  του πομπού· με την κεραία της συσκευασίας (~2 dBi ≈ 0 dBd) είναι περίπου 14 dBm ERP. Με κεραία
  μεγαλύτερου κέρδους **χαμήλωσε** το `LORA_TX_DBM` ανάλογα.
- **Duty cycle:** ο κώδικας υπολογίζει τον χρόνο στον αέρα από SF/BW/CR και μετά από κάθε
  εκπομπή **δεν ξαναεκπέμπει** πριν περάσει 100 × αυτός ο χρόνος (το ρολόι RTC μετρά και στον
  ύπνο). Αν η πόρτα ανοιγοκλείνει συνεχώς, στέλνεται η **τελευταία** κατάσταση μόλις επιτραπεί.

| SF (125 kHz, CR 4/5) | Χρόνος στον αέρα (24 bytes) | Ελάχιστη απόσταση εκπομπών |
|---|---|---|
| 7 | 62 ms | ~6 s |
| 9 (προεπιλογή) | 206 ms | ~21 s |
| 10 | 371 ms | ~37 s |
| 12 | 1483 ms | ~2,5 λεπτά |

Ένα γεγονός πόρτας στέλνεται 2 φορές (`LORA_EVENT_REPEATS`), άρα μετρά διπλά.
Εκτός Ευρώπης ισχύουν άλλες ζώνες και όρια: άλλαξε συχνότητα και έλεγξε τον τοπικό κανονισμό.

## 9. Αντιμετώπιση προβλημάτων, όρια, ασφάλεια

| Σύμπτωμα | Τι να κοιτάξεις |
|---|---|
| `ΛΑΘΟΣ ΡΥΘΜΙΣΗ` | `LORA_KEY_HEX` δεν είναι 64 hex ή `LORA_NODE_ID` είναι 0 |
| `SX1276 not found` | λάθος pins (RESET 14 ή 23;), ή πλακέτα με SX1262 |
| η πύλη γράφει `REPLAY/old counter` | έσβησες όλη τη flash του κόμβου (χάθηκε ο μετρητής): στην πύλη κράτα πατημένο το PRG 3 s στην εκκίνηση |
| η πύλη δεν ακούει τίποτα | διαφορετικά SF/BW/συχνότητα/κλειδί, κεραία, απόσταση |
| ξυπνά συνέχεια | η επαφή «παίζει» ή το pin δεν έχει pull-up (GPIO34–39 θέλουν εξωτερικό) |
| η μπαταρία τελειώνει γρήγορα | LED/OLED/ρυθμιστής της πλακέτας (βλ. παρακάτω) |

- **Πιστοποίηση, όχι κρυπτογράφηση.** Όποιος ακούει στα 868 MHz βλέπει θερμοκρασία και κατάσταση
  πόρτας. Δεν μπορεί να φτιάξει ή να αλλάξει πακέτο χωρίς το κλειδί (tag 64 bit) ούτε να
  ξαναπαίξει παλιό (μετρητής). **Μπορεί** όμως να παρεμβάλει (jamming) ώστε να μη φτάσει το
  πακέτο· τότε η πύλη θα βγάλει `lora_node_lost` μετά από 3 περιόδους, όχι αμέσως.
- **Δεν υπάρχει ACK.** Ένα πακέτο που χάθηκε (σύγκρουση, απόσταση) δεν ξαναστέλνεται· η κατάσταση
  διορθώνεται στην επόμενη περιοδική αποστολή. Μην το θεωρείς συναγερμό ασφαλείας.
- **Το κλειδί είναι κοινό** για όλους τους κόμβους και βρίσκεται στη flash: όποιος κλέψει έναν
  κόμβο μπορεί να μιμηθεί τους άλλους. Άλλαξε κλειδί αν χαθεί κόμβος.
- **Μετρητής:** ζει στη μνήμη RTC και «δεσμεύεται» στο NVS ανά 64 πακέτα. Μετά από αλλαγή
  μπαταρίας συνεχίζει από το επόμενο μπλοκ (πάντα προς τα πάνω). Ένα απλό upload δεν τον σβήνει·
  το «Erase All Flash» ναι.
- **Κατανάλωση:** το ESP32 κοιμάται στα ~10 µA, αλλά οι πλακέτες TTGO/Heltec έχουν OLED, LED
  και ρυθμιστή που τραβούν από εκατοντάδες µA έως μερικά mA στον ύπνο. Μην περιμένεις «χρόνια»
  από αυτές χωρίς τροποποίηση· μέτρησε τη δική σου.

**Πιθανότερα σημεία προσαρμογής σε πραγματικό υλικό:** pins RESET/μπαταρίας ανά αναθεώρηση
πλακέτας, ο συντελεστής `BATT_DIVIDER`, η πολικότητα και το pull-up της επαφής, και το αν η
πλακέτα σου οδηγεί την κεραία από το PA_BOOST (όλες οι RFM95/TTGO/Heltec SX1276 το κάνουν).
