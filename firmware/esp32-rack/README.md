# NetWatch Rack (ESP32)

Αισθητήρας περιβάλλοντος για **rack / ντουλάπι δικτύου**. Μετρά και στέλνει στο NetWatch
(HTTPS, «πρωτόκολλο αισθητήρα», τύπος **`rack`**):

| Τι | Πώς | Στο NetWatch |
|---|---|---|
| Θερμοκρασία, υγρασία | SHT31 σε I2C (0x44 ή 0x45), με έλεγχο CRC | `status.temp`, `status.hum`, γεγονότα `temp_high`, `humid_high` |
| Πόρτα | μαγνητική επαφή (reed), interrupt + debounce | `metrics.door`, γεγονός `door_open` |
| Νερό | δύο ακροδέκτες σε ADC **ή** έτοιμο ψηφιακό module | `metrics.leak`, γεγονός `water_leak` |
| Ρεύμα | PZEM-004T v3 (Modbus-RTU, UART2) | `metrics.volt/amp/watt/kwh/freq/pf`, γεγονότα `power_fail`, `power_back` |

Κάθε αισθητήρας είναι **προαιρετικός**. Ο SHT31 και το PZEM ανιχνεύονται μόνοι τους στην
εκκίνηση: μια πλακέτα με σκέτο SHT31 δουλεύει χωρίς καμία αλλαγή. Η πόρτα και το νερό δεν
μπορούν να ανιχνευτούν (ένα άδειο pin «μοιάζει» με ανοιχτή πόρτα): αν δεν τα έχεις, βάλε
`USE_DOOR 0` / `USE_LEAK 0`.

> **Δοκιμασμένο μόνο σε compile· δεν έχει τρέξει σε πραγματικό υλικό.** Δες την ενότητα 8
> για το τι είναι πιθανότερο να θέλει ρύθμιση.

## 3. Συνδεσμολογία

| Αισθητήρας | Ακροδέκτης αισθητήρα | ESP32 | Σημείωση |
|---|---|---|---|
| SHT31 | VIN / GND | 3V3 / GND | ποτέ 5 V στο I2C |
| SHT31 | SDA / SCL | GPIO21 / GPIO22 | τα breakout έχουν ήδη pull-up |
| Reed πόρτας | δύο καλώδια | GPIO27 και GND | εσωτερικό pull-up· κλειστή πόρτα = LOW |
| Νερό, 2 ακροδέκτες (`USE_LEAK 1`) | ακροδέκτης Α | GPIO25 μέσω **10 kΩ** | τάση μόνο τη στιγμή της μέτρησης |
| | ακροδέκτης Β | GPIO34 | και **1 MΩ** από το GPIO34 στο GND |
| Νερό, module (`USE_LEAK 2`) | VCC / GND / DO | 3V3 / GND / GPIO34 | τα περισσότερα δίνουν LOW όταν βραχούν |
| PZEM-004T v3 | 5V / GND | **3V3** / GND | βλ. παρακάτω |
| | TX | GPIO16 (RX2) | |
| | RX | GPIO17 (TX2) | |

**PZEM και στάθμες:** η πλευρά TTL του PZEM είναι οπτικά απομονωμένη από το δίκτυο και
τροφοδοτείται από το pin «5V». Αν της δώσεις **3,3 V** μιλά σε στάθμες 3,3 V (ασφαλές για το
ESP32). Σε ορισμένες πλακέτες με 3,3 V το RX του PZEM δεν «ανάβει» τον οπτοζεύκτη· τότε
τροφοδότησέ το με 5 V και βάλε διαιρέτη τάσης (π.χ. 1 kΩ / 2 kΩ) στη γραμμή TX → GPIO16.

**Πλευρά 230 V του PZEM:** L και N στους ακροδέκτες τάσης, ο CT γύρω από **έναν** αγωγό (τη
φάση). Είναι δουλειά **αδειούχου ηλεκτρολόγου**, με το κύκλωμα εκτός τάσης.

**Γιατί GPIO34 για το νερό:** το Wi-Fi χρησιμοποιεί τον ADC2, άρα μόνο τα pins του ADC1
(GPIO32–39) δουλεύουν. Τα 34–39 είναι μόνο είσοδοι και **δεν** έχουν εσωτερικές αντιστάσεις.

**Πού μπαίνει το ESP32:** σε πρίζα/USB του **UPS**. Το PZEM τροφοδοτείται από τη γραμμή που
μετρά· όταν κοπεί το ρεύμα σωπαίνει, και ακριβώς αυτό (ή τάση < 50 V) γίνεται `power_fail`.
Αν το ESP32 δεν είναι σε UPS θα σβήσει κι αυτό και θα δεις απλώς «αισθητήρας εκτός σύνδεσης».

## 4. Ρύθμιση και σύζευξη

```bash
cd ~/netwatch/firmware/esp32-rack
cp secrets.example.h secrets.h
```

1. Στο NetWatch: **🧩 Οι συσκευές μου → κάρτα «Rack» → Δημιουργία κωδικού → Αντιγραφή**.
2. Στο `secrets.h`: `WIFI_SSID`, `WIFI_PASS` και ο κωδικός στο `NW_PAIR_CODE` (`NW1.…`).
3. Όρια: `TEMP_HIGH_C` / `TEMP_HYST_C`, `HUMID_HIGH_PCT` / `HUMID_HYST_PCT`.
4. `USE_…` ανάλογα με το τι έχεις συνδέσει.

Ο κωδικός σύζευξης περιέχει το token του αισθητήρα **και** το αποτύπωμα SHA-256 του
πιστοποιητικού του NetWatch. Το firmware ελέγχει το αποτύπωμα σε κάθε σύνδεση και, αν δεν
ταιριάζει, **δεν στέλνει τίποτα** (ούτε το token). Δεν υπάρχει «ανασφαλής» λειτουργία.

**Υστέρηση:** `temp_high` βγαίνει όταν η θερμοκρασία περάσει το όριο (δύο συνεχόμενες
μετρήσεις). Νέα ειδοποίηση θα βγει μόνο αφού πρώτα πέσει κάτω από `όριο − υστέρηση`.

## 5. Flash

### arduino-cli

```bash
cd ~/netwatch/firmware/esp32-rack
arduino-cli compile --fqbn esp32:esp32:esp32 --library ../common .
arduino-cli upload  --fqbn esp32:esp32:esp32 -p /dev/cu.usbserial-0001 .   # Linux: /dev/ttyUSB0
arduino-cli monitor -p /dev/cu.usbserial-0001 -c baudrate=115200
```

### Arduino IDE

1. Boards Manager: **esp32 by Espressif** (3.x).
2. Μία φορά: `ln -s "$(cd ../common && pwd)" ~/Documents/Arduino/libraries/NetWatchSignedOta`
   (η κοινή βιβλιοθήκη· το ίδιο link με τα Sentinel/Canary).
3. Άνοιξε το `esp32-rack.ino`, Board **ESP32 Dev Module**, θύρα, **Upload**.
4. Serial Monitor στα **115200**.

Στην εκκίνηση θα δεις τι βρέθηκε (`[sht31] found at 0x44`, `[pzem] found: 231.4 V 50.0 Hz`),
το `[nw] paired as p-…` και κάθε 10 s μια γραμμή `[rack] temp=… hum=… door=…`.

## 6. Τι θα δεις στο NetWatch

Στην κάρτα του αισθητήρα: θερμοκρασία, υγρασία, πόρτα, διαρροή, τάση/ρεύμα/ισχύς/kWh/Hz/PF,
σήμα Wi-Fi, χρόνος λειτουργίας. Αναφορά κάθε 60 s (`REPORT_INTERVAL_S`)· τα **γεγονότα φεύγουν
αμέσως**. Αν το Wi-Fi ή το NetWatch λείπει, κρατιούνται έως 12 γεγονότα στην ουρά και
στέλνονται μόλις επανέλθει (με πεδίο `ago` = πόσα δευτερόλεπτα πριν έγιναν).

```json
{"status":{"fw":"1.0.0","hw":"ESP32 + SHT31 + reed + PZEM-004T","ip":"192.168.1.61","mac":"a4:cf:12:aa:bb:cc",
  "uptime":8123,"heap":201344,"rssi":-58,"interval":60,"temp":27.4,"hum":41.2,
  "metrics":{"volt":231.4,"amp":0.812,"watt":176.3,"kwh":12.481,"freq":50.0,"pf":0.94,"door":false,"leak":false}},
 "events":[{"type":"door_open","detail":"Άνοιξε η πόρτα του rack","data":{"door":true}}]}
```

Γεγονότα: `temp_high`, `humid_high`, `door_open`, `water_leak`, `power_fail`, `power_back`.

## 7. Αντιμετώπιση προβλημάτων

| Σύμπτωμα στο Serial | Τι να κοιτάξεις |
|---|---|
| `[nw] NOT PAIRED: …` | λείπει/κόπηκε ο κωδικός στο `NW_PAIR_CODE` (πρέπει να αρχίζει με `NW1.`) |
| `CERT MISMATCH … token NOT sent` | το NetWatch έφτιαξε **νέο** πιστοποιητικό (νέα εγκατάσταση;) ή κάποιος παρεμβάλλεται. Κάνε νέα σύζευξη· αν δεν άλλαξες τίποτα, ερεύνησέ το |
| `HTTP 401: sensor unknown/removed` | ο αισθητήρας διαγράφηκε στο NetWatch: νέα σύζευξη |
| `connect … failed` | η θύρα αισθητήρων (8790) είναι κλειστή, άλλο VLAN, ή firewall |
| `[sht31] not found` | SDA/SCL ανάποδα, τροφοδοσία, διεύθυνση (γέφυρα ADDR → 0x45) |
| `[pzem] no reply` | TX/RX ανάποδα, η πλευρά 230 V χωρίς τάση, στάθμες 3,3/5 V (βλ. ενότητα 3) |
| η πόρτα δείχνει ανάποδα | `DOOR_OPEN_LEVEL LOW` |
| ψευδείς συναγερμοί νερού | ανέβασε το `LEAK_WET_MV`, έλεγξε το 1 MΩ προς GND |

## 8. Όρια και ασφάλεια

- **Μόνο ανάγνωση.** Στο PZEM στέλνεται αποκλειστικά η εντολή Modbus `0x04` (read input
  registers). Ποτέ εγγραφή διεύθυνσης, ποτέ μηδενισμός ενέργειας.
- Η θερμοκρασία είναι του σημείου όπου βρίσκεται ο SHT31· βάλ' τον ψηλά, στην έξοδο του αέρα.
- Ο SHT31 έχει ακρίβεια ±0,3 °C / ±2 %RH· το PZEM ±0,5 %. Δεν είναι πιστοποιημένα όργανα.
- Το `power_fail` προϋποθέτει ESP32 σε UPS **και** PZEM που έχει απαντήσει τουλάχιστον μία φορά
  από την εκκίνηση (αλλιώς δεν ξέρουμε αν υπάρχει καν PZEM).
- Ένα άνοιγμα-κλείσιμο πόρτας μικρότερο από ~60 ms (`DOOR_DEBOUNCE_MS`) αγνοείται σκόπιμα.
- Το `secrets.h` περιέχει κωδικό Wi-Fi και token: μένει εκτός git, και όποιος έχει φυσική
  πρόσβαση στην πλακέτα μπορεί να τα διαβάσει από τη flash (δεν υπάρχει flash encryption).

**Πιθανότερα σημεία προσαρμογής σε πραγματικό υλικό:** στάθμες/τροφοδοσία της πλευράς TTL του
PZEM, κατώφλι και αντιστάσεις του αισθητήρα νερού (`LEAK_WET_MV`), πολικότητα της επαφής
(`DOOR_OPEN_LEVEL`), και pins αν η πλακέτα σου δεν βγάζει τα 16/17 (π.χ. modules WROVER).
